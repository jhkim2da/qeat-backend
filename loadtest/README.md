# 공개 메뉴 조회 부하 테스트

손님이 QR을 찍으면 호출되는 `GET /api/public/tables/{tableToken}`를 대상으로, Redis 메뉴 캐시를 껐을 때와 켰을 때를 비교했습니다.

## 요청 한 번에 나가는 쿼리

`SHOW_SQL=true`로 Redis를 비운 뒤 같은 토큰으로 두 번 호출해 확인했습니다.

| 상황 | 쿼리 |
| --- | --- |
| 캐시 미스 | 테이블+부스 조인 1개, 메뉴 1개 |
| 캐시 적중 | 테이블+부스 조인 1개 |

테이블 조회는 QR 토큰이 유효한지 확인해야 하므로 캐시와 관계없이 매번 DB로 갑니다. 캐시가 줄이는 것은 메뉴 쿼리 1개와 메뉴 엔티티 변환입니다.

## 환경

- MacBook Air (Apple Silicon) 한 대에서 앱, MySQL 8.4(Docker), Redis 7.4(Docker), k6를 함께 실행
- 데이터: 승인된 부스 1개, 테이블 100개, 메뉴 20개 (`seed.sql`)
- k6 `constant-arrival-rate`, 각 단계 60초, 테이블 토큰 100개 중 무작위
- `SHOW_SQL=false`, 앱 시작 후 초당 100건으로 10초 워밍업
- 각 조건을 1회씩 측정했습니다. 앱과 부하 도구가 같은 노트북 자원을 나눠 쓰므로 절대값보다 두 조건의 차이와 경향을 봐야 합니다.

## 결과

| 목표 RPS | 캐시 | 실제 처리량 | avg | p95 | p99 | 실패 | 보내지 못한 요청 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 300 | 끔 | 300/s | 3.63ms | 4.83ms | 16.95ms | 0% | 0 |
| 300 | 켬 | 299/s | 6.69ms | 4.70ms | 49.33ms | 0% | 36 |
| 800 | 끔 | 800/s | 2.00ms | 2.46ms | 13.70ms | 0% | 0 |
| 800 | 켬 | 800/s | 2.55ms | 2.60ms | 41.47ms | 0% | 0 |
| 1500 | 끔 | 1,484/s | 7.80ms | 9.94ms | 174.61ms | 0% | 940 |
| 1500 | 켬 | 1,474/s | 17.21ms | 43.42ms | 507.69ms | 0% | 1,574 |
| 3000 | 끔 | **2,135/s** | 456ms | 692ms | 910ms | 0% | 50,272 |
| 3000 | 켬 | **2,471/s** | 393ms | 534ms | 630ms | 0% | 30,711 |

## 해석

- **초당 800건까지는 캐시 유무와 관계없이 p95 5ms 이하**였습니다. 축제 당일 실제 트래픽보다 훨씬 큰 부하에서도 캐시 없이 충분했습니다.
- **포화 구간(목표 3000)에서는 캐시를 켰을 때 최대 처리량이 약 16% 높고(2,135 → 2,471/s), p95가 약 23% 낮았습니다(692 → 534ms).**
- 1500 구간은 캐시를 켠 쪽이 더 느리게 나왔습니다. 1회 측정이고 한계 직전 구간이라 변동이 커서, 이 결과만으로 캐시가 느리다고 보지는 않습니다. 반복 측정이 필요합니다.
- 기대보다 효과가 작은 이유는 캐시를 켜도 요청마다 테이블 조회 1개가 남고, 20개짜리 메뉴 조회는 인덱스로 이미 싸기 때문입니다. 캐시는 DB 쿼리 1개를 Redis 왕복과 JSON 역직렬화로 바꾸는 것이라 비용 차이가 크지 않습니다.
- 과부하에서도 실패 응답은 0건이었고, 요청을 버리지 않는 대신 대기 시간이 늘었습니다.

## 다음에 확인할 것

- 같은 조건 3회 반복 측정으로 변동 폭 확인
- 포화 지점의 병목이 CPU(앱과 k6가 같은 노트북), Tomcat 스레드, DB 커넥션 풀 중 어디인지 확인
- `spring.jpa.open-in-view`가 기본값(켜짐)이라 요청이 끝날 때까지 DB 커넥션을 잡고 있는 영향 확인

## 다시 실행하기

```bash
# 1. 앱을 한 번 실행해 테이블을 만든 뒤 데이터 넣기
docker exec -i qeat-mysql sh -c 'mysql --default-character-set=utf8mb4 -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"' < loadtest/seed.sql

# 2. 캐시를 끄거나 켜고 앱 실행
SHOW_SQL=false PUBLIC_MENU_CACHE_ENABLED=false ./gradlew bootRun

# 3. 다른 터미널에서 측정
k6 run -e RATE=100 -e DURATION=10s loadtest/public-menu.js   # 워밍업
k6 run -e RATE=3000 loadtest/public-menu.js
```
